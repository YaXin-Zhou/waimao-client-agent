# 配置化业务与背调字段

## 目标

系统不把客户所在行业、主营服务、搜索关键词或背调项目写死在代码中。客户在创建获客任务时，可以自行维护业务目录、关键词、目标市场和需要核实的字段；后续搜索、背调、评分和导出都读取这份配置。目标客户是否匹配，由官网是否有客户所配置业务的公开证据决定。

## 配置模型

### 业务目录 `business_offerings`

每项业务包含：

- `name`：展示名称
- `key`：稳定的 `snake_case` 标识
- `description`：给研究流程的业务说明
- `keywords`：用于搜索和匹配的关键词

### 背调字段 `research_fields`

每项字段包含：

- `name`、`key`、`description`、`keywords`
- `type`：`text`、`number`、`boolean` 或 `select`
- `required`：是否要求输出该字段
- `evidence_required`：是否必须附来源
- `human_review`：是否进入人工复核
- `options`：选择型字段的允许值

## 当前客户默认配置

新建任务会预填一组可编辑的默认项：

- 业务目录：注塑件、CNC 机加工、模具与工装。
- 背调字段：公司主体信息、官网与联系方式、主营产品与业务定位、行业与业务需求匹配、采购与决策层信息、过往采购品类。

这些只是表单初始值，客户可以删除、修改或继续添加；它们不是固定的行业规则。搜索关键词、目标市场和客户类型仍由客户自由填写。

## 真实性规则

关键词只是发现信号，不是事实。字段结果必须带 `status`、`confidence`、`sources` 和 `checked_at`。无法从当前来源确认时输出 `unknown` 和空来源；多个来源冲突时输出 `conflicting`，不能用模型猜测补齐。

## 已完成边界

当前版本已完成领域模型、任务 API 接收与更新（`PATCH /api/tasks/{id}/criteria`）、SQLite 持久化、研究提示词动态生成、配置业务相关性评分信号、研究结果 API 返回和 CSV 动态列导出，并兼容没有配置新字段的历史任务。前端已支持创建时配置，以及对已有任务重新编辑业务目录和背调字段；字段结果会显示状态、置信度和来源链接。

多来源采集基础已完成：研究流程会抓取主来源及线索中声明的其他来源，保留来源 URL，并将模型返回的来源限制在实际抓取来源内；附加来源失败不会覆盖主来源结果。

证据质量闭环已支持：多来源候选值不一致时确定性标记 `conflicting`；搜索档案国家与官网背调国家不一致时标记 `country_conflict` 并要求人工复核；本地前端可在保留来源的前提下将字段人工确认写回，且无来源的字段不能直接标记为 `verified`；来源数量按真实证据数组展示。
