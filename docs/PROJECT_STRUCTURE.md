# 项目文件与目录规范

## 1. 总体结构

```text
waimaogongzuoliu/
├── CONTEXT.md                 # 领域词汇和业务边界，只记录稳定概念
├── README.md                  # 项目入口和开发纪律
├── .gitignore                 # 密钥、运行数据和工具产物排除规则
├── .dockerignore              # 容器构建上下文排除规则
├── Dockerfile.api             # API 可复现镜像构建文件
├── docker-compose.yml          # API 本地部署编排
├── pyproject.toml             # Python 依赖、格式化、测试和静态检查配置
├── package.json               # 前端依赖和脚本（若采用前端工程）
├── config/                    # 配置模板和环境配置说明，不放真实密钥
│   ├── README.md
│   └── .env.example
├── src/                       # 可部署业务源码
│   ├── domain/                # 客户、任务、邮件、评分等领域模型和规则
│   ├── application/           # 用例和工作流编排，不直接依赖具体外部服务
│   ├── infrastructure/       # 数据库、AI、搜索、网页、阿里邮箱等适配器
│   ├── interfaces/            # HTTP API、后台任务入口、命令行入口
│   └── frontend/              # 页面、组件和前端状态管理（如采用独立前端）
├── tests/                     # 与 src 分层对应的自动化测试
│   ├── unit/                  # 纯函数、领域规则和状态转换
│   ├── integration/           # 数据库、适配器和工作流集成
│   ├── contract/              # 外部服务接口契约
│   └── e2e/                   # 浏览器和完整业务流程
├── docs/                      # 需求、架构、决策和运行手册
│   ├── requirements/          # 需求基线、用户故事、验收标准
│   ├── architecture/          # 架构图、数据流和接口设计
│   ├── adr/                   # 需要记录取舍的架构决策
│   └── runbooks/              # 部署、备份、故障恢复和操作手册
├── scripts/                   # 可重复执行的开发、测试、迁移和运维脚本
├── integrations/              # WorkBuddy 等外部平台的适配和分发材料
│   └── workbuddy/              # 内部使用的本地 Skill 与参考文档
├── data/                      # 本地运行数据；真实数据默认不入库
│   ├── fixtures/              # 脱敏测试样例，可提交
│   ├── runtime/               # 数据库、队列等运行产物，不提交
│   ├── uploads/               # 用户上传文件，不提交
│   └── exports/               # 导出表格，不提交
└── logs/                      # 本地日志，不提交
```

## 1.1 当前目录盘点

以下目录属于正常的运行或构建产物，不属于源码：

```text
data/runtime/   # 当前 SQLite 运行库
data/backups/   # 可恢复的数据库备份
data/exports/   # 用户导出的客户表格
logs/           # 本地运行日志
dist/           # 前端构建产物
node_modules/   # 前端依赖安装目录
.pytest_cache/  # pytest 缓存
.ruff_cache/    # ruff 缓存
```

这些目录已经由 `.gitignore` 排除。备份和导出中可能包含真实数据，不能在未确认的情况下删除；缓存和构建目录可由开发者在确认不需要时单独清理。

## 2. 源码分层规则

### `src/domain`

只放业务概念和业务规则，例如客户档案、评分规则、邮件状态和任务状态转换。不能导入 SMTP、IMAP、HTTP、数据库或具体 AI SDK。

### `src/application`

只放业务用例，例如创建获客任务、清洗客户、生成背调、审核开发信和执行跟进。通过接口调用基础设施，不绑定具体服务商。

### `src/infrastructure`

只放外部依赖适配器，例如搜索提供商、网页读取器、模型提供商、数据库和阿里邮箱。更换服务商时，尽量只修改这一层。

### `src/interfaces`

只负责把 HTTP、队列或命令行输入转换为应用用例调用，不在路由中编写评分、清洗和发信业务规则。

### `src/frontend`

只负责展示、交互、表单校验和调用接口。客户评分、邮件安全规则等核心业务规则必须由后端领域层负责。

## 3. 文档分类规则

- 需求变化写入 `docs/requirements/` 和变更记录。
- 模块关系、数据流和接口约定写入 `docs/architecture/`。
- 只有难以逆转、存在明显取舍的决定才写入 `docs/adr/`。
- 部署、备份、恢复、邮箱配置和日常操作写入 `docs/runbooks/`。
- 稳定业务词汇只写入根目录 `CONTEXT.md`，不在各模块重复定义冲突术语。

## 4. 文件放置禁令

- 不在根目录直接堆放业务源码、临时脚本、导出表格或日志。
- 不把密钥、真实客户资料、真实邮箱密码写入代码或配置模板。
- 容器镜像不复制 `config/.env`、运行数据库、日志或导出文件；这些内容必须在运行时挂载。
- 不在接口层、页面组件或脚本中复制业务规则。
- 不为了临时验证把测试文件放入 `src/`。
- 不创建没有职责说明的目录。

## 5. 新模块检查清单

新建模块前必须说明：所属领域、输入输出、依赖方向、持久化数据、失败处理、测试位置和文档位置。通过评审后再创建目录和代码。
