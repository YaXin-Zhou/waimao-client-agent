# 合格客户交付规则

## 目的

系统会把符合条件的客户全部保存为合格客户，不把合格结果截断为固定数量。
每日发送数量只是发送安排：当天优先安排目标数量，其余合格客户进入“待联系”，不足目标时继续追加搜索。

## 可配置规则

每个获客任务独立保存以下配置，不把行业或客户业务写死在代码中：

| 配置 | 默认值 | 作用 |
| --- | ---: | --- |
| `qualified_lead_limit` | 30 | 兼容旧配置；现在作为每日目标的备用值，不限制合格客户入库 |
| `candidate_limit` | 接口默认至少 100 | 搜索阶段最多采集的候选数量 |
| `minimum_qualification_score` | 40 | 进入交付名单的最低评分 |
| `require_public_email` | true | 是否要求官网公开邮箱 |
| `daily_limit` | 30 | 每日发送安排目标；不限制搜索结果和合格客户入库 |

## 硬性过滤规则

满足以下任一条件的候选不会进入工作台交付列表：

- 没有可访问的官方网站；
- 任务要求公开邮箱，但官网没有提取到公开邮箱；
- 匹配评分低于任务门槛；
- 国家等关键事实存在冲突，尚未人工复核。

系统不会推测邮箱，也不会为了凑够数量把无邮箱或业务不匹配的公司放进最终名单。

## 结果和证据

候选记录仍然全部写入 SQLite，便于追溯。每条未入选记录会保存 `rejection_reasons`，例如：

- `missing_public_email`
- `missing_product_evidence`
- `score_below_threshold`
- `missing_website`
- `conflicting_country`

如果官网公开邮箱的域名与官网域名不同，系统会增加 `email_domain_mismatch` 标记。这不是自动判定为假邮箱：企业可能使用国家域名、集团域名或品牌邮箱，最终仍需人工根据官网证据确认。

工作台默认展示全部 `qualified=true` 的合格客户。数据库会按评分和每日目标划分“今日发送”和“待联系”，候选池与过滤原因继续保留，不会丢失采集结果。

## 真实数据边界

官网公开邮箱只能证明“公司存在公开联系渠道”，不能自动证明它是采购决策人邮箱。需要决策人职位、LinkedIn 或更完整联系人数据时，应通过客户授权的 Apollo 等外部数据源适配器补充，并保留来源、抓取时间和授权边界。
