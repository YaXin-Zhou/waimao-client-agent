# 背调执行层

## 目标

把一次背调从“调用流程”提升为可追踪、可重试、可恢复的执行记录，为后续任务暂停、人工审核和失败重跑提供稳定边界。

## 状态

```text
RUNNING
   ├─ 成功且证据充分 ──────> SUCCEEDED
   ├─ 成功但证据不足 ──────> REVIEW_REQUIRED
   └─ 达到重试上限/不可恢复错误 -> FAILED
```

## 规则

- 每次执行都有唯一运行记录，保存任务、域名、状态、尝试次数和最后错误。
- 网络连接、超时和操作系统 I/O 错误允许按配置次数重试。
- 结构化结果校验等不可恢复错误不重试，直接记录失败并交给上层处理。
- 背调完成不等于自动通过；证据不足时进入 `REVIEW_REQUIRED`，必须人工核验。
- 运行记录与背调报告分开保存：运行记录描述执行过程，报告描述业务结论。
