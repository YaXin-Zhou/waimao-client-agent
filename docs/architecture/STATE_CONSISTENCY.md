# 状态与事实边界改造图

## 目标

让页面显示的每一个客户、背调、草稿和任务状态都能回到 API 和持久化记录；外部依赖失败时只显示失败，不降级成虚构结果。

## 数据流

```text
┌──────────────┐
│ 用户填写条件 │
└──────┬───────┘
       ▼
┌──────────────┐     失败/超时/容量满
│ API 校验      │──────────────────────┐
└──────┬───────┘                      ▼
       ▼                       ┌──────────────┐
┌──────────────┐                │ 失败 + 审计  │
│ 持久化任务    │                │ 可重试       │
└──────┬───────┘                └──────────────┘
       ▼
┌──────────────┐
│ 背调步骤      │ queued → fetching → analyzing
│              │ → scoring → persisting → completed
└──────┬───────┘
       ▼
┌──────────────┐
│ 真实来源证据  │──┐
└──────────────┘  │
                  ▼
┌────────────────────────────┐
│ 字段状态                    │
│ verified / inferred / unknown│
└──────────────┬─────────────┘
               ▼
┌────────────────────────────┐
│ 前端只展示 API 持久化结果    │
│ API 失败时显示错误，不显示假数据│
└──────────────┬─────────────┘
               ▼
┌────────────────────────────┐
│ 草稿 → 人工审核 → 安全闸门  │
└────────────────────────────┘
```

## 不变量

1. 没有来源证据的行业、规模、采购意向不得填充为确定事实。
2. `unknown`、失败、空任务和未生成草稿必须有明确界面状态。
3. 审核按钮必须调用真实审核接口；状态只有接口成功后才能更新。
4. 任务切换期间清空旧客户选择，不能把旧任务数据显示在新任务下。
5. 邮箱未配置时不连接、不读取、不发送，并明确显示配置状态。
6. 任何发送相关动作都必须保留快照、人工确认和审计记录。

## 本轮验证边界

```text
已完成：本地 API、真实官网背调、持久化、评分回写、幂等、重试、异常状态和安全边界
暂缓：真实阿里 IMAP/SMTP、真实回复和发送失败恢复
未宣称：生产部署完成、客户正式验收完成、自动化群发完成
```
