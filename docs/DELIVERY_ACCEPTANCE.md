# 交付与验收清单

## 当前可以确认的范围

- 本地 SQLite 数据、真实官网证据、客户状态和审核事件可以持久化。
- 研究任务支持本地后台队列、重试、幂等键和前端进度展示。
- 阿里邮箱具备只读 IMAP 适配器；未配置时不连接。
- 回复规则分类不调用大模型，并对退信、投诉和低置信度内容要求人工复核。
- 发送接口要求草稿批准、人工确认和内容快照一致；未完成确认不会调用 SMTP。

## 必须由客户或专用测试环境完成

- 配置专用阿里测试邮箱，完成一次真实 IMAP 收信、同步、去重和线程关联。
- 用真实回信验证报价、交期、投诉、退信和拒绝分类。
- 用专用测试邮箱完成人工确认后的 SMTP 发送、回信、退信和失败恢复。
- 确认客户正式产品、目标市场、发件人身份、发送额度和黑名单规则。
- 确认部署主机、备份周期、恢复责任人、日志留存时间和访问权限。

## 运行检查

- `GET /api/health`：进程存活检查。
- `GET /api/ready`：核心依赖就绪检查。
- `python scripts/backup_runtime.py`：创建不覆盖旧文件的 SQLite 备份。
- 发生恢复操作前，先停止 API、复制当前数据库到隔离目录，再由负责人确认备份可读；本项目不提供自动删除旧数据的命令。

## 交付结论

当前版本是可审计的本地工作流原型，尚未通过真实邮箱和客户正式验收，因此不能宣称生产环境闭环完成。只有上述真实邮箱、发送失败恢复、部署恢复和客户确认全部完成后，阶段 6 才能标记完成。
