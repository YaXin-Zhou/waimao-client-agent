# WorkBuddy 外贸客户开发助手接入架构

更新时间：2026-09-09

## 一、方案结论

当前外贸客户智能系统适合以 **WorkBuddy Buddy 应用** 作为用户入口，通过 **MCP Connector** 连接现有业务后端，再配合 Skill 和 Automation 形成完整的外贸获客工作流。

```text
WorkBuddy Buddy 应用
  ├── 外贸工作模式
  ├── 场景入口
  ├── 业务 Skill
  ├── 定时 Automation
  └── MCP Connector
          ↓
外贸客户智能系统后端
  ├── Google 搜索
  ├── 官网抓取
  ├── 数据清洗与去重
  ├── 客户背调与评分
  ├── 多语言邮件生成
  ├── 回信分析与跟进
  ├── 阿里 SMTP / IMAP
  └── 客户数据与审计日志
```

## 二、WorkBuddy 原生功能对应关系

| WorkBuddy 功能 | 在本项目中的职责 |
|---|---|
| Buddy 应用 | 外贸客户开发助手的统一产品入口和品牌界面 |
| 工作模式 | 固定外贸业务规则、数据真实性规则和人工审核边界 |
| 场景胶囊 | 一键启动搜索客户、官网背调、生成邮件、分析回信等任务 |
| MCP Connector | 连接现有 Python 后端并调用业务工具 |
| Skill | 规范 AI 的调用顺序、参数、异常处理和输出格式 |
| Automation | 定时搜索客户、整理数据并生成待审核草稿 |
| Project | 保存客户资料、表格、项目文档和历史上下文 |

## 六、部署建议

### 当前阶段：客户电脑本地部署

```text
客户电脑
├── WorkBuddy
├── 外贸客户智能系统
│   ├── React 前端
│   ├── Python API
│   ├── SQLite 数据库
│   └── 本地配置文件
├── 浏览器
├── FlClash 代理
└── 阿里邮箱 SMTP / IMAP
```

优点：部署成本低，邮箱密码和 API Key 可以留在客户电脑，适合小规模试用。

### 后续阶段：服务器或企业内网部署

```text
WorkBuddy
    ↓ HTTPS + MCP
云服务器 / 企业内网服务
    ├── 外贸客户智能系统 API
    ├── 数据库
    ├── 密钥管理
    ├── 任务队列
    └── 审计和备份
```

如果 WorkBuddy 使用远程 MCP，服务端需要 HTTPS、身份认证、最小权限和稳定可达地址；如果使用本地 MCP，则可以让 WorkBuddy 在客户电脑上调用本地服务。

## 七、安全边界

```text
WorkBuddy 负责：
  接收自然语言任务、编排流程、展示结果

业务后端负责：
  数据清洗、评分、邮箱连接、审计和安全规则

人工用户负责：
  核验客户、确认语言、审核邮件、确认发送
```

以下操作不能由自然语言直接无确认执行：

- 真实发送邮件
- 修改邮箱配置
- 删除客户数据
- 批量导出敏感数据
- 修改黑名单和发送额度

## 八、推荐产品形态

```text
WorkBuddy Buddy 应用
  ├── 工作模式：外贸客户开发
  ├── 场景胶囊：搜索 / 背调 / 写信 / 回信分析
  ├── MCP 连接器：连接外贸客户系统
  ├── Skill：规范业务流程
  ├── Automation：定时生成客户和待审核草稿
  └── Project：保存客户资料、表格和历史文档
```

核心分工：

```text
WorkBuddy = 入口、编排、Skill、自动化
当前系统 = 搜索、背调、数据、邮件、审计
人工人员 = 最终审核和发送确认
```
