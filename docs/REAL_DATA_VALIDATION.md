## 核验规则

一条客户记录只有同时满足以下条件，才可进入合格客户列表：

1. 官网 URL 可访问；
2. 公司名称和官网来源保持关联；
3. 公开邮箱来自官网首页、联系页或官网明确链接的公开页面；
4. 邮箱格式有效，不是图片文件名、占位地址或明显系统地址；
5. 每条邮箱保留来源 URL 和页面摘录；
6. 未能确认的字段不补猜测，显示为未知或待复核。

## 发现并修复的问题

真实页面核验时发现，部分电商页面会把图片资源名中的 `@2x.png`、`@2x.svg` 误识别为邮箱，页面还可能包含 `contoso@example.com` 等示例地址。现已在领域清洗层和官网采集层同时过滤：

- 图片、图标等非邮箱文件扩展名；
- `example.com`、`domain.com`、`contoso.com` 等占位域名；
- `noreply`、`no-reply` 系统地址；
- 单条联系人复查与批量搜索使用同一套多页抓取和清洗逻辑。

修复后已重新抓取上述 5 个官网，脏数据不再出现在结果中。

## 当前限制

- Google 静态 HTTP 请求可能返回 JavaScript/Consent 页面；系统会明确报错，不会把空结果伪装成搜索成功。当前真实批次通过可见浏览器结果导入；
- 官网没有公开邮箱、需要登录、验证码或完全由 JavaScript 渲染时，系统不能保证拿到邮箱；
- “公开邮箱存在”不等于邮箱一定有人使用，正式发送仍需人工审核；
- 公司规模、成立时间、决策人等字段只有在公开来源明确出现时才会填充。

## 2026-09-09 抓取质量回归

本次对官网有限抓取策略做了收口：在抓取预算有限且产品链接较多时，联系、Impressum、法律信息页优先级高于普通关于页，同时保留产品相关页和配置关键词命中页。这样可以同时保留产品匹配证据和公开邮箱来源，不依赖固定网站路径。

另外，导航链接不足时会有限读取同域 `sitemap.xml` 或 `sitemap_index.xml`，最多展开 4 个站点地图入口，不抓取外域，也不把站点地图本身当作客户证据。

网页采集器同时支持常见的公开邮箱反混淆写法（例如 `[at]`、`(at)`、`[dot]`、`(dot)`），规范化后仍会经过占位域名、系统地址和邮箱格式检查，并保留原始页面片段作为证据。

客户池漏斗还会显示独立官网来源数量和多来源核验客户数量；“多来源核验”只统计同一客户至少有 2 个不同的非搜索来源 URL，不把搜索结果页当作真实性证据。

搜索候选在进入页面抓取前按规范化官网主机名去重，因此同一公司不同路径（例如 `/about` 和 `/products`）不会重复占用候选名额；首次出现的结果页面作为入口，后续由官网有限抓取补充证据。

客户详情中的来源等级由持久化来源确定性计算：无来源、仅搜索来源、单一官网来源、多来源核验。它是证据覆盖度标记，不是模型给出的真实性百分比，也不替代人工复核。

客户档案和漏斗会单独显示同域来源与外部关联来源数量；外部来源即使来自官网明确链接，也不会被静默当作同域事实。

只要存在外部关联来源，档案状态会显示“已关联、待人工确认”；系统不根据外链存在本身判定主体一致。

外部页面进入证据前还会做身份词交叉匹配：官网标题或域名中的有效身份词，必须出现在外部链接、页面标题或正文中；匹配失败的外链不会进入客户资料。

客户详情还会对公司名、国家、邮箱和产品分别显示来源字段核验状态；字段未在非搜索来源片段中找到时，只标记为未找到，不会用搜索摘要或模型结论补齐。

已有的邮箱域名不一致、国家来源冲突也会在字段核验中显示为“来源冲突”，不会被“来源已找到”覆盖。

客户列表和客户详情现在共用同一套历史来源清洗与资格刷新路径，避免详情页重新显示已经被列表过滤掉的无效证据。
