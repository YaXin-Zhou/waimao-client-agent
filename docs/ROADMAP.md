# 外贸客户智能工作流路线图

## 路线图结论

核心本地功能已完成，当前只保留条件性真实回信验证和外部搜索源可用性验证。每个阶段都有独立的完成标准；外部网站受限时必须明确失败，不用假数据补齐。本轮不新增业务能力，只继续收口现有阶段的状态、事实边界、文档和验收证据。

## 阶段 0：真实搜索与证据质量闸门（已完成本地实现）

目标：保证搜索候选经过官网内容、公开邮箱和来源证据筛选后再进入合格客户池。

已完成：静态 Google 请求、无界面 Chrome fallback、可选备用来源边界、官网正文证据、邮箱清洗、来源证据清洗、历史记录兼容和失败不造假；真实任务已验证 5 条历史客户档案中无图片文件名或占位邮箱来源。当前 Google 在本机触发异常流量时返回明确 503，未写入新记录。

当前边界：Bing 适配器默认关闭，曾做过真实相关性抽检但结果不稳定；启用前必须重新验证相关性。

## 阶段 1：客户状态与审计时间线（已完成）

目标：把客户从“搜索结果”变成可追踪的业务对象。

交付：客户状态枚举、合法状态转换、状态变更审计、前端时间线、状态转换测试。

完成标准：客户状态变更不可越级；每次变更都有操作者、原因、时间和前后状态；刷新页面后状态不丢失。已通过真实客户页面完成 `new → awaiting_score` 验证。

## 阶段 2：真实研究任务编排（进行中）

目标：让搜索、官网抓取、清洗、评分和背调成为可恢复的持久任务。

交付：任务队列、任务步骤、超时、重试上限、幂等键、失败原因和进度展示。

当前已完成的垂直切片：研究运行记录已持久化；研究执行服务已接入官网抓取、模型研究、评分和报告保存；评分结果会回写内存/SQLite 客户档案，刷新后保持一致；支持按配置的最大尝试次数重试；新增 `POST /api/tasks/{task_id}/leads/{domain}/research` 启动单条背调，新增 `GET /api/tasks/{task_id}/research-runs` 查询运行记录；本地后台队列返回 `202` 并异步执行；支持请求幂等键；前端可提交任务、轮询状态并在完成后自动刷新研究报告；模型未配置、参数缺失和失败会返回明确错误，不伪造成功；研究运行现在会持久化记录 `抓取官网 → 分析内容 → 计算评分 → 保存报告` 的细粒度步骤，并兼容历史 `executing` 状态。

当前仍待完成：生产级分布式队列。单任务超时治理已落地：研究运行持久化 `timeout_seconds`，执行链在步骤边界检查整体截止时间；官网抓取和 DeepSeek 请求也分别使用可配置的底层网络超时。队列容量保护已落地：`RESEARCH_QUEUE_WORKERS` 与 `RESEARCH_QUEUE_MAX_PENDING` 可通过配置调整，超过容量会明确拒绝并要求稍后重试。当前已支持本地进程重启时根据持久化输入恢复 `running` 研究任务，但仍不能宣称具备生产级分布式任务能力。

完成标准：外部网站超时或模型失败时不会重复写入客户，也不会丢失任务状态；可从失败步骤继续。本地切片已验证真实官网异步背调、运行状态持久化、自动刷新、幂等、细粒度步骤、进程重启恢复、队列容量和单任务超时；生产级分布式队列仍未完成。

## 阶段 3：阿里邮箱只读接入（进行中）

目标：先安全读取收件箱，建立邮件线程，不发送邮件。

交付：邮箱配置、连接测试、IMAP 同步、邮件线程、去重、退信识别和同步审计。

当前已完成的垂直切片：新增只读 IMAP 配置和阿里邮箱适配器；只读解析 RFC822 邮件正文、Message-ID、In-Reply-To、References、主题和时间；按 Message-ID 去重；按客户主域名关联邮件；识别常见退信；新增收件邮件 SQLite 持久化和只读 API；邮箱未配置时明确返回未配置，不尝试连接，也不暴露凭据；同步结果写入审计事件；线程接口同时提供原始邮件和按 `thread_key` 聚合的线程摘要；新增 `POST /api/mailbox/test`，只验证登录和只读打开，不读取邮件。

当前已完成专用阿里邮箱的真实 IMAP 只读连接、同步、去重和系统通知识别；客户真实回信闭环仍需真实来信触发后验收。SMTP 和自动发送不属于邮箱读取阶段。

完成标准：专用测试邮箱完成一次收信、同步、去重和线程关联；凭据不进入数据库、日志或前端。当前真实收件中已确认系统欢迎邮件不会被当成客户回复。

## 阶段 4：回复分类与跟进建议（进行中）

目标：根据真实回信生成分类、问题提取和跟进建议。

交付：意向分类、报价/交期/投诉/退信等安全标签、回复建议草稿、待办和人工复核。

当前已完成的垂直切片：同步邮件可按确定性规则分类为意向、报价、交期、投诉、退信、拒绝或其他；输出置信度、风险等级、证据词和安全跟进建议；投诉、退信和低置信度内容自动要求人工复核；分析结果按 Message-ID 持久化并可通过 API 查询；这一步不调用大模型，可节省 token；规则已覆盖中文、英文、德文、法文、西文、意大利文和葡萄牙文的常见业务信号；对需要继续处理的分类按 Message-ID 幂等创建人工跟进待办，支持待处理、处理中、已完成和已取消状态，前端可更新状态。

当前仍待完成：真实邮件样本验收、复杂多语言内容的模型升级策略，以及正式测试邮箱上的待办闭环验收。待办领域已完成本地持久化和前端状态更新，但未用无来源的示例来证明真实邮件闭环。

完成标准：高风险内容只生成建议；低置信度结果进入人工队列；每条建议关联原始邮件。当前规则分类和安全建议已通过测试，等待阶段 3 的真实收件邮件后进行端到端验收。

## 阶段 5：发送安全闸门（进行中）

目标：在人工确认后，通过阿里邮箱发送已批准内容。

交付：SMTP 发送、重复发送检查、黑名单、每日额度、最近联系时间、附件检查、发送审计和失败重试。

当前已完成的垂直切片：新增纯业务发送前检查；未人工批准的草稿、无效收件人、黑名单邮箱/域名和已达每日额度会被阻止；即使检查通过也始终要求人工确认；新增 `POST /api/drafts/{draft_id}/send-check`，返回检查结果并明确 `sending_performed: false`；新增带配置开关的阿里 SMTP 适配器和人工确认快照发送用例，发送尝试会持久化并可查询；发送前支持请求方传入最近联系标记，以及附件数量、扩展名和路径安全检查；发送安全服务现在会根据历史成功发送记录和可配置天数自动判断最近联系，调用方不必手工维护该布尔值；附件元数据支持单文件大小和总大小限制。

当前已完成一次受控真实 SMTP 发送验证；客户回复、退信和附件真实内容类型仍不在本轮继续扩展范围内。

完成标准：必须人工确认收件人、主题、正文和发送动作。当前安全闸门和一次受控 SMTP 发送已验证，自动群发仍明确禁止。

## 阶段 6：生产化与客户验收（进行中）

目标：让系统具备部署、恢复、监控和客户交付能力。

交付：权限、密钥管理、结构化日志、备份恢复、部署说明、操作手册、客户验收报告和遗留问题清单。

当前已完成的工程收口：新增 `/api/ready` 核心依赖就绪检查；新增不覆盖旧备份的 SQLite 备份脚本，并完成一次真实备份的独立读取和 `integrity_check=ok` 验收；新增不记录请求体和敏感字段的 JSON 结构化请求日志；新增只输出布尔状态的本地配置检查脚本，并确认 `config/.env` 不进入 Git；新增基于已持久化证据的 CSV 客户明细导出脚本；新增 API 容器部署文件，配置只读挂载、运行数据和日志独立挂载，并已在本机完成 Compose 解析、镜像构建、容器内配置检查及备用端口实际启动健康检查；新增交付与验收清单，明确真实邮箱、部署恢复和客户确认不能由本地 Fake 测试替代；完成背调评分、官网证据回写、状态审计一致性修复，补充内存/SQLite 集成测试，并清理前端未接入的假入口。

当前仍待完成：正式主机的权限/密钥注入方案、跨进程队列恢复、真实邮箱闭环、生产主机部署演练和客户签字验收。本地配置状态检查、结构化请求日志、就绪检查、备份脚本和 API 镜像构建已完成。

完成标准：使用客户真实产品、真实官网和专用真实邮箱完成完整闭环，并由客户确认结果。当前文档和就绪检查已完成，但尚未达到客户验收标准。

## 当前不进入实现的内容

- 自动无审核群发。
- 没有来源证据的行业、规模和采购意向推断。
- 用固定示例数据掩盖 API 或外部网站失败。
- 把“草稿已批准”显示成“邮件已发送”。
- 在没有客户授权前接入客户正式邮箱。

## 阶段推进规则

每个阶段固定执行：

```text
需求卡片 → 领域设计 → 接口设计 → 实现 → 单元测试
→ 集成测试 → 真实页面验证 → 文档更新 → Git 提交 → 下一阶段计划
```

当前工作边界：本地工程切片、真实官网背调、数据质量闸门和邮箱安全边界已收口；真实客户回信分类闭环需等待真实来信；正式部署、恢复演练和客户确认按当前决定跳过。不继续扩展业务功能。
