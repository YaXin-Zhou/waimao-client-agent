# 外贸客户智能工作流路线图

## 路线图结论

从当前版本开始，还剩 **6 个主要阶段**。每个阶段都有独立的完成标准；未通过当前阶段验收，不进入下一阶段。

## 阶段 1：客户状态与审计时间线（已完成）

目标：把客户从“搜索结果”变成可追踪的业务对象。

交付：客户状态枚举、合法状态转换、状态变更审计、前端时间线、状态转换测试。

完成标准：客户状态变更不可越级；每次变更都有操作者、原因、时间和前后状态；刷新页面后状态不丢失。已通过真实客户页面完成 `new → awaiting_score` 验证。

## 阶段 2：真实研究任务编排（进行中）

目标：让搜索、官网抓取、清洗、评分和背调成为可恢复的持久任务。

交付：任务队列、任务步骤、超时、重试上限、幂等键、失败原因和进度展示。

当前已完成的垂直切片：研究运行记录已持久化；研究执行服务已接入官网抓取、模型研究、评分和报告保存；支持按配置的最大尝试次数重试；新增 `POST /api/tasks/{task_id}/leads/{domain}/research` 启动单条背调，新增 `GET /api/tasks/{task_id}/research-runs` 查询运行记录；本地后台队列返回 `202` 并异步执行；支持请求幂等键；前端可提交任务、轮询状态并在完成后自动刷新研究报告；模型未配置、参数缺失和失败会返回明确错误，不伪造成功。

当前仍待完成：跨进程/重启后的队列恢复、细粒度官网抓取/模型分析/评分步骤、失败任务从断点继续，以及队列容量和超时治理。当前队列是本地进程内实现，不能宣称已经具备生产级分布式任务能力。

完成标准：外部网站超时或模型失败时不会重复写入客户，也不会丢失任务状态；可从失败步骤继续。当前已验证真实官网一次异步背调成功、运行状态持久化、自动刷新和幂等模型单元测试；因尚未完成跨进程恢复和断点续跑，阶段 2 仍未完成。

## 阶段 3：阿里邮箱只读接入（进行中）

目标：先安全读取收件箱，建立邮件线程，不发送邮件。

交付：邮箱配置、连接测试、IMAP 同步、邮件线程、去重、退信识别和同步审计。

当前已完成的垂直切片：新增只读 IMAP 配置和阿里邮箱适配器；只读解析 RFC822 邮件正文、Message-ID、In-Reply-To、References、主题和时间；按 Message-ID 去重；按客户主域名关联邮件；识别常见退信；新增收件邮件 SQLite 持久化和只读 API；邮箱未配置时明确返回未配置，不尝试连接，也不暴露凭据。

当前仍待完成：专用测试邮箱的真实 IMAP 连接、同步审计事件、按线程聚合的接口展示，以及与后续回复分类的领域契约。SMTP 和任何自动发送仍不在本阶段范围内。

完成标准：专用测试邮箱完成一次收信、同步、去重和线程关联；凭据不进入数据库、日志或前端。当前已完成 Fake 邮件解析、同步去重和本地安全边界验证，尚未完成真实测试邮箱验收。

## 阶段 4：回复分类与跟进建议

目标：根据真实回信生成分类、问题提取和跟进建议。

交付：意向分类、报价/交期/投诉/退信等安全标签、回复建议草稿、待办和人工复核。

完成标准：高风险内容只生成建议；低置信度结果进入人工队列；每条建议关联原始邮件。

## 阶段 5：发送安全闸门

目标：在人工确认后，通过阿里邮箱发送已批准内容。

交付：SMTP 发送、重复发送检查、黑名单、每日额度、最近联系时间、附件检查、发送审计和失败重试。

完成标准：必须人工确认收件人、主题、正文和发送动作；完成专用测试邮箱的发送、收信、退信和失败恢复验收。

## 阶段 6：生产化与客户验收

目标：让系统具备部署、恢复、监控和客户交付能力。

交付：权限、密钥管理、结构化日志、备份恢复、部署说明、操作手册、客户验收报告和遗留问题清单。

完成标准：使用客户真实产品、真实官网和专用真实邮箱完成完整闭环，并由客户确认结果。

## 当前不进入实现的内容

- 自动无审核群发。
- 没有来源证据的行业、规模和采购意向推断。
- 用固定示例数据掩盖 API 或外部网站失败。
- 把“草稿已批准”显示成“邮件已发送”。
- 在没有客户授权前接入客户正式邮箱。

## 阶段推进规则

每个阶段固定执行：

```text
需求卡片 → 领域设计 → 接口设计 → 实现 → 单元测试
→ 集成测试 → 真实页面验证 → 文档更新 → Git 提交 → 下一阶段计划
```

当前正在执行阶段 2；阶段 3 的入口条件是研究任务的进度、失败恢复和幂等验收通过。
